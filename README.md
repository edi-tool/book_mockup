# cover_image（立体書影さん）

印刷用の展開カバーPDFから、判型・背幅を反映した立体書影（PNG）をブラウザ内で作るツール。
公開予定 https://edi-tool.github.io/cover_image/

PDF選択 → 判型・背幅・綴じ → 仕上がり範囲調整 → 面の確認 → 角度 → PNG保存。生成AI・外部API・サーバー処理・解析タグなし。PDFは端末外へ送らない。

## 使い方

1. カバーPDF（表4・背・表1が横に並んだ展開PDF）を選ぶかドロップする。複数ページなら対象ページを選び、必要なら90°回転。
2. 判型（B5 182×257 / A5 148×210 / 四六 127×188 mm）を選び、背幅をmmで入力（0.1〜100、0.1mm単位）。綴じ方向（左綴じ＝左から表4・背・表1、右綴じ＝逆）を選ぶ。
3. 枠をトンボの仕上がり線に合わせる。枠の比率は (2×判型幅＋背幅):判型高さ で固定。ドラッグで移動、四隅で拡縮、矢印キーで0.1mm（Shiftで1mm）、`[` `]` で幅、Ctrl/⌘＋ホイール・ピンチ・`+` `-` で表示拡大。拡大時は見えている範囲をPDFから高精細に描き直す。
4. 切り出した3面を確認する。
5. 角度（正面・表1＋背・表1＋小口・表4＋背・表4正面・斜め俯瞰、微調整あり）、背景（透過/白）、サイズ（1200/2000/3000px正方形）、影を選んで保存。出力名は `元ファイル名_mockup_角度_判型_背幅_サイズ.png`。

## 品質と制約

- 出力時はPDFから必要解像度（出力サイズに応じて最大400ppi相当、テクスチャ上限まで）で再描画する。プレビューの拡大ではない。枠全体を1回描いて累積境界で3面に切り分け（16MP超は面ごとに描画）、縮小した場合は画面に表示する。
- 正面・表4正面は正投影で、表紙の色・形を変えない（検証: 合成PDFの色と出力画素が一致）。斜めは画角20°の望遠相当の透視。光は弱い固定陰影のみで、反射・トーンマッピングなし。
- CMYK・特色・オーバープリント・透明効果はPDF.jsが画面用RGBに変換する。色校正ではない。
- 並製本・単冊のみ。帯・上製本・自由視点・一括書き出しは未対応（[docs/SPEC.md](docs/SPEC.md) のP1）。
- WebGL2が使えない環境では、表1の平面画像（影つき）だけを保存できる。
- PDF.jsは描画を requestAnimationFrame で進めるため、描画中にタブを裏へ回すと戻るまで止まる。
- 透明効果を多用したPDFはPDF.jsの解析・描画が重く、初回表示や書き出しに数十秒かかることがある（実例で初回33秒・2000px書き出し25秒、GPUなし環境）。

## 開発

```powershell
python -m http.server 8000
```

```powershell
npm test
```

```powershell
npm run check
```

- 依存パッケージなし（Node 22以上で `node:test`）。CIは `.github/workflows/ci.yml`（edi-tool 共通テンプレート）。
- 構成: `js/crop-geometry.js`（寸法・枠の純粋関数）、`js/views.js`（角度・構図）、`js/output.js`（解像度・ファイル名・空画像判定）、`js/pdf-adapter.js`（PDF.js）、`js/crop-editor.js`（範囲エディタ）、`js/book-renderer.js`（Three.js）、`js/compose.js`（影・背景）、`js/app.js`（配線）。
- 合成テストPDFは `npm run fixtures`（`scripts/make-test-pdf.mjs`）で再生成する。実際の書籍PDF・生成書影はリポジトリに置かない（`.gitignore` とテストで検査）。
- 同梱ライブラリと参考コードのライセンスは [lib/THIRD_PARTY.md](lib/THIRD_PARTY.md)。
